# Kobayashi · протокол сравнения двух моделей

В [ноутбуке](../notebooks/kobayashi.ipynb) сопоставлены обычный трансформер и трансформер с гиперсетью. Для каждой архитектуры завершены три обучения по 100 000 шагов в реконструкции Connected+. Гиперсеть дала меньшую финальную MSE на знакомых парах во всех трёх запусках. На отложенных парах преимущество зависело от сида. Основные конфигурации — [обычный трансформер](../configs/experiments/kobayashi.yaml) и [hypernetwork](../configs/experiments/kobayashi_hyper.yaml). Обе используют один teacher и одинаковые seed потоков данных, поэтому сравниваются на одних задачах. Меняется архитектура и предусмотренные статьёй настройки оптимизации.

## Зафиксированная постановка

Источник: [Kobayashi et al., версия v1, §3 и приложения C.1–C.4](https://arxiv.org/html/2407.12275v1#A3), проверено 14 ноября 2026. Авторская реализация именно этих опытов в доступных материалах не обнаружена. Это самостоятельный PyTorch-код с явными решениями там, где статья не даёт деталей; численная эквивалентность авторскому коду не заявляется.

Учитель состоит из шести матриц `16×16` и фиксированного readout. В эпизоде выбираются две компоненты, коэффициенты получаются из экспоненциальных величин по Algorithm 1; их сумма равна **1.5**, а не 1. Матрица смеси делится на спектральную норму. Входы равномерны на `[-√3,√3]`. Connected+ содержит 12 пар; пары `(0,3), (1,4), (2,5)` удержаны. Индексация в коде начинается с нуля.

Ванильная модель получает числовые токены `(x,y)`, у последнего запроса метка обнулена. Hypernetwork выводит код по демонстрациям и завершающему нулевому токену; запрос передаётся только исполнителю. Матрицы исполнителя и readout обучаются с нуля и не получают параметры учителя. Обе модели используют pre-LN, GELU, относительное позиционное смещение и **двунаправленное attention**. Вся супервизия скрыта от `predict`: передаются только `x` и `context_y`.

Основные размеры, optimizer, learning rate, weight decay, batch size, gradient clipping и 100 000 шагов взяты из C.4. Полные значения находятся в YAML. Сохранённые шесть запусков выполнены на Apple MPS в FP32.

## Выбранные детали реконструкции

Эти настройки доступны в конфигурации и не выдаются за установленные авторские параметры:

- **64 контекстных примера + запрос.** Длина не задана в просмотренном приложении. Для обеих моделей даём одинаковое число демонстраций. Hypernetwork не получает истинную метку запроса; неоднозначность обозначений `N` в C.3.2 не разрешаем утечкой ответа.
- **Truncated normal:** границы ±2 исходных σ, затем коррекция дисперсии до заявленного teacher standard deviation. Инициализация воспроизводима через отдельный `task_seed`; сами teacher tensors сохраняются вместе с состоянием задачи. В статье не указан порог усечения и не уточнена конвенция стандартного отклонения.
- **T5-style relative bias:** 32 двунаправленных bucket, максимальное расстояние 128, отдельная обучаемая таблица в каждом блоке. В статье не заданы эти детали.
- **Инициализация студента:** normal(0,0.02) для линейных слоёв/relative bias, нулевые biases; для модулей hypernetwork масштаб учитывает размер входа и латента. Финальная LayerNorm отключена. Readout hypernetwork без bias; веса его первого слоя — линейная комбинация обучаемых модулей без дополнительной спектральной нормировки.
- AdamW `betas=(0.9,0.999)`, cosine без warmup; детали реализации scheduler и checkpoint задаёт общий runner. Это фиксированные рабочие решения, не повод считать запуск точным совпадением со статьёй.

Smoke-конфигурация уменьшает пространство входов, контекст, ширину и число шагов. Она сохраняет шесть модулей и split, но представляет другой размер задачи. Её результат нельзя смешивать с основными графиками.

## Что сохраняется и измеряется

Каждый оценочный эпизод хранит входы, демонстрации, ответ, полный `z`, mask и идентификатор пары. Учитель сохраняется отдельно через `Task.state_dict`; одного seed для долгосрочного восстановления недостаточно. Имена, перечисление пар и граница train/test проверяются при загрузке.

Основные величины — MSE ответа и ошибка предиктора среднего контекстных ответов. Общий runner считает `paper_r2 = 1 - mean(mse) / mean(context_mean_mse)` по всему банку. **Усреднение отношения ошибок по отдельным эпизодам неверно:** знаменатель отдельного запроса может быть почти нулевым. В исходном описании C.2 термин R² сопровождается формулировкой про нормированную MSE; сохраняются обе исходные ошибки и явная формула нашего score. Дополнительно ошибки разбиваются по каждой паре модулей.

`diagnostics` снимает residual последнего токена после входной проекции и каждого блока. Линейный декодер восстанавливает все шесть коэффициентов. Обучается на независимом `probe_train`; слой и ridge выбираются только по ID `validation`; итоговые банки — `id_test` и удержанный `test`. Сохраняются коэффициенты probe, нормировка признаков, decoded codes, ответы внешнего исполнителя, ошибки и разрезы по парам. Для ванильной модели признаки включают доступ к запросу; для hypernetwork inference-признаки от запроса не зависят.

Контроли повторяют тот же алгоритм выбора: перемешанные коды обучающего банка и независимо инициализированная необученная модель. Ни test-ответы, ни OOD-коды не участвуют в выборе decoder. Для внешнего расчёта используется **полный необработанный** decoded code и известный teacher. Нулевая или нечисловая матрица даёт invalid, число таких случаев сохраняется; при их наличии агрегированная ошибка executor не сообщается как результат только удачных примеров. Успех привилегированного исполнителя не доказывает, что сам трансформер выполняет те же вычисления.

Оценивание промежуточных checkpoint позволяет построить динамику ответа, восстановления кода и исполнения. Не следует подбирать конфигурацию по этим итоговым OOD-графикам и затем называть тот же тест независимым подтверждением. Проверки connected/disconnected support, новый случайный teacher и изменения длины контекста остаются отдельными расширениями; текущая серия покрывает Connected+ и сравнение двух архитектур.
